# Bili_monkey 🐒

BiliAutoClicker 的油猴客户端，独立仓库，分离 HTML 模板。

## 文件说明

| 文件 | 说明 |
|------|------|
| `biliauto-tampermonkey-client.user.js` | 油猴脚本主文件，通过 `GM_getResourceText` + 镜像 raw 链接加载外部模板 |
| `template.html` | 独立的 UI 模板文件（样式 + HTML 结构 + `<template>` 子模板），托管在 GitHub 并走镜像加速 |
| `zh-cn.woff2` | 面板标题用的 `SDK_SC_Web Heavy` 子集字体（仅含 UI 实际用到的字形，约 88KB） |

> 字体已从原始 12MB 全量 CJK 字体子集化为约 88KB 的 woff2（仅保留粗体标题实际用到的字形，视觉无差异）；正文/任务名仍走系统字体栈 `Segoe UI / PingFang SC / Microsoft YaHei`。

## 国内镜像加速

模板资源引用通过 `gh-proxy.com` 镜像加速，确保国内用户能快速加载。

## 使用方式

1. 安装油猴扩展（Tampermonkey）
2. 点击脚本安装链接（从 release 或 raw 链接获取）
3. 访问 B 站奖励兑换页面（`award-exchange.html`），右下角会出现悬浮按钮
4. 首次使用需登录：点击面板 → 获取验证码 → 发送到指定群聊完成授权

## 面板配置项

在任务卡片中可为每个 `task_id` 单独配置：

| 配置 | 说明 |
|------|------|
| **开始时间** | 抢码触发时间，支持多种写法（见下）。留空使用默认值 |
| **点击间隔** | 连点间隔（秒），默认 0.05s |
| **持续时长** | 连点总时长（秒），默认 10s |
| **点击模式** | `DOM点击`（默认，安全）/ `直接API`（绕过页面节流，有触发风控封 IP 的风险） |

保存后配置持久化在油猴存储中；命中服务端 AI 解析到的每日抢码时间时，会自动回填「开始时间」（并提前 3 秒）。

## 开始时间支持的输入格式

`开始时间` 输入框会自动规范化，支持：

- **绝对时刻**：`20:00:00`、`20:00:00.500`（含毫秒）、`20点`、`20点半`、`20点30分`
- **相对延时**：`30秒后`、`1分30秒后`、`+30`（30 秒后）、`+1h30m`
- **立即执行**：`现在` / `立即` / `马上` / `now` / `+0`
- **跨天**：`明天 08:00:00`

## 点击模式说明

- **DOM 点击**：模拟点击页面「领取」按钮，走页面自身逻辑，受页面 1 秒节流限制，安全。
- **直接 API**：直接调用页面 Vue 组件的领取方法绕过节流。⚠️ 频率过高可能触发 B 站风控导致 IP 被封，建议配合代理或降低频率。

## 时间校准与精确调度

脚本会从 B 站直播 RTC 接口拉取服务器时间，补偿本地时钟偏差。调度采用**主线程精确定时器**（远端粗粒度 `setTimeout`、临近逐级加密、最后 ≤10ms 自旋命中目标时刻），并以 **Web Worker 心跳 + 可见性/焦点事件**作为后台节流时的后备触发，全部汇入一个**幂等**的触发点（同一目标只会执行一次）。

关键点：**触发路径不含任何网络请求**——`offset` 由自适应校准（临近目标前完成、最后 5 秒不再发起网络）提前备好，到点时只读缓存值，避免把网络往返注入临界路径导致点击延后。日志面板可查看当前偏差并手动重新校准。

## 执行互斥与跨标签页冲突

同一 IP 下并发抢码会让请求量成倍抬高，触发 B 站风控的概率大幅上升，因此脚本有两层互斥：

1. **同页互斥**：页面主流程与调度器共用一把 `Panel.state.running` 锁。主流程自己等待并连点时会撤销已武装的调度定时器，调度器触发时若发现已有任务在跑会直接跳过；面板「执行」按钮在已有任务等待/执行时也不再强制解锁重跑。
2. **跨标签页互斥**：每个标签页通过油猴存储 `bm_cross_tab_claims` 登记「本页要抢的 `task_id` + 校准后的目标时刻」，并由 Web Worker 心跳保活。其它页签读取时**只在「同一 `task_id` 且两个目标时刻相差 ≤ 60 秒」时才判定为冲突**——时刻不同意味着不会并发打同一接口，静默处理不打扰用户。

判定为冲突时：

- 排期时先弹一次警告（面板提示 + 日志面板 + 状态栏），建议关闭多余标签页；
- 到点瞬间会再复核一次，若冲突仍在，本页**主动让出**本次执行（日志标记「跨页让出」），避免两路同时请求同一接口。

如确实需要多页签并发抢码（例如同一账号多设备），在油猴脚本存储中把 `bm_allow_parallel` 设为 `true` 即可放行，默认禁止。

## GitHub 镜像版本检查（只提示，不强更）

脚本启动时会通过国内镜像 `gh-proxy.com` 拉取仓库里的脚本头部，解析 `@version` 与本地 `CONFIG.VERSION` 比较：

- 发现新版本 → 顶部弹一条**可关闭的横幅**（`发现新版本 x.y.z（当前 a.b.c）`）+ toast 提示 + 日志面板记录，**不会阻塞页面，也不会强制更新**；
- 点击横幅「立即更新」→ 在**新标签页**打开镜像安装链接，由油猴弹出更新确认（不打断当前页面的抢码），也可直接在油猴扩展里更新；
- 点击「稍后」→ 记录 `bm_gh_dismissed_version`，同一版本不再打扰，直到出现更新的版本；
- 检查失败（断网 / 镜像挂了）→ 降级为一条日志，**不影响抢码主流程**；镜像失败会自动回落到 `raw.githubusercontent.com` 直连。

检查结果缓存 6 小时，不会每次打开页面都下载整个脚本。

相关油猴存储项：

| 键 | 说明 |
|------|------|
| `bm_gh_latest_version` / `bm_gh_checked_at` | 镜像端最新版本号与检查时间（内部缓存） |
| `bm_gh_dismissed_version` | 被点「稍后」忽略的版本号 |
| `mirror_prefix` | 镜像前缀，默认 `https://gh-proxy.com/`，可换成别的加速服务 |

> 服务端 `/api/versions/latest` 的**强制更新**机制仍然保留且独立：只有服务端 `force_update` 为真、且版本确实更新时才弹阻塞遮罩。

## 调试

调试日志默认关闭。如需排查问题，在油猴的脚本存储中将 `debug_mode` 设为 `true` 后刷新页面，即可在控制台看到 `[BiliAuto]` 详细日志。

## 开发说明

- 这是**单文件油猴脚本**，无构建步骤。修改后需同步更新 `@version` 与脚本内的 `CONFIG.VERSION`（版本号比较用 `Util.compareVersion`，分段数值比较，`1.10.0 > 1.9.0` 判定正确）。
- 走 `GM_xmlhttpRequest` 的域名必须列进 `@connect`（当前：`bili.982835785.xyz`、`api.live.bilibili.com`、`gh-proxy.com`、`raw.githubusercontent.com`）。
- 模板变量：主骨架用 `${CONFIG.KEY}` / `${CONFIG.KEY?'a':'b'}` 在加载时替换；运行期动态内容一律走 `<template id="tmpl-*">` + `{{KEY}}` 占位机制（见 `Panel.getSubTemplate`）。
- 网络拦截 hook 只有一份实现 `installNetworkHooks(win)`，同时用于 `unsafeWindow` 直接安装与页面上下文注入两条路径。
